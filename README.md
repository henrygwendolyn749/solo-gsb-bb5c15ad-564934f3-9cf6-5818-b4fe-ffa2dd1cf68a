# 口述史事件时间线核对

供口述史整理者核对多个事件“先后描述”是否自洽的小工具。整理者把访谈中得到的两事件时间差区间逐行粘贴，后端把全部区间联立为**差分约束系统**：

- 若约束互相矛盾，返回一条由**原始行号与对应上下界**构成的**闭合矛盾链**（负环），说明是哪几句话“打了架”；
- 若无矛盾，返回一条以**最早事件为第 0 分钟**、满足全部区间的可行时间线，并逐条核对每个区间；
- 联立通过后可做**约束冗余核对**：任选一条原始行，删去它的上下界约束后，用其余约束推导这两个事件时间差的最紧区间——推导区间完全落在该行区间内判为**可删**（冗余转述），否则判为**必要**，并给出有界端点的推导路径（原始行号与所用界值）作为证据。

技术栈：Python 3.11 + FastAPI + 原生 JavaScript（无前端构建、无 npm）。

## 输入格式

每行一条：

```
事件甲,事件乙,最少分钟,最多分钟
```

含义：`最少分钟 ≤ 事件乙时刻 − 事件甲时刻 ≤ 最多分钟`（即“乙比甲晚”的时间差区间，分钟为整数；允许负数表示乙实际更早）。

- 支持半角 `,` 与中文逗号 `，`；
- 空行会被跳过，但**行号按原始文本计算**，矛盾链与错误提示引用的都是原始行号；
- 每行校验：事件名非空、上下界为整数、下界不大于上界。

示例（无冲突）：

```
起床,洗漱,10,30
洗漱,早饭,15,45
早饭,出门,20,60
出门,开会,40,90
起床,开会,80,240
```

页面上可一键填充“可行示例”与“矛盾示例”。

## 页面操作

1. 启动服务后，浏览器打开 **http://localhost:8080**（端口固定 8080，见下文启动命令）；
2. 把访谈整理出的区间逐行粘贴进文本框，点击 **联立核对**：
   - 校验未通过 → 按原始行号列出每行问题；
   - 区间冲突 → 展示闭合矛盾链（行号、上下界、逐步关系式）；
   - 无冲突 → 展示可行时间线与逐条核对表；
3. 无冲突时，页面底部出现 **约束冗余核对** 卡片：在下拉框中选择一条原始行，点击 **核对所选行**：
   - **可删（冗余）**：删去该行后，其余约束仍必然推出该行的时间差区间，页面给出推导区间与两个端点的推导路径（原始行号、所用界值、逐步关系式）；
   - **必要（不可删）**：推导区间超出该行区间（或某端点无界），页面说明哪个端点失守及原因；
   - 若在核对前改动了文本导致输入无效或约束冲突，页面自动回退展示原有的校验错误或矛盾链。

## 单条启动命令（Docker Compose）

```bash
docker compose up -d --build
```

启动后打开浏览器访问：

**http://localhost:8080**

> 页面地址与端口固定为 **8080**。如宿主机 8080 被占用，修改 `compose.yaml` 中 `ports` 的左侧值（如 `"9090:8080"`）即可，容器内端口保持 8080。

停止：

```bash
docker compose down
```

查看日志：

```bash
docker compose logs -f
```

docker build -t oral-history-timeline .

## 原理简介

对每行 `甲,乙,lo,hi` 建立两条最短路约束：

- `t乙 − t甲 ≤ hi`：边 `甲 → 乙`，权 `hi`（上界）
- `t甲 − t乙 ≤ −lo`：边 `乙 → 甲`，权 `−lo`（下界）

再加一个指向所有事件、权为 0 的虚拟源（实现上等价于所有距离初始化为 0），运行 Bellman-Ford：

- 第 N 轮仍能松弛 ⇒ 存在负环，沿前驱指针还原负环，并映射回每条边的**原始行号与上/下界值**，即页面展示的闭合矛盾链（环上权值之和 < 0，意味着推出 `0 < 0` 式的矛盾）；
- 否则得到一组可行时刻，整体平移令最小值为 0，即为“最早事件在第 0 分钟”的时间线。

**约束冗余核对**：删去所选行的两条边后（原系统一致，删边不会产生负环），`t乙 − t甲` 的最紧上界等于 `甲 → 乙` 的最短路长度，最紧下界等于 `乙 → 甲` 最短路长度的相反数；端点不可达即该端**无界**。推导区间 `[下界, 上界]` 完全落入所选行区间 ⇒ 该行可删（其余叙述必然满足它），否则必要。页面同时展示有界端点的最短推导路径（原始行号、所用界值与逐步关系式）。

## API

- `GET /` — 页面
- `GET /api/health` — 健康检查
- `POST /api/solve` — 请求体 `{"text": "甲,乙,30,60\n..."}`，返回：
  - `status: "ok"`：`timeline`（事件与分钟）、`differences`（逐条核对）；
  - `status: "conflict"`：`conflict.steps`（矛盾链每一环的行号、方向、上/下界与含义）；
  - `status: "error"`：`errors`（逐行校验错误，含原始行号）。
- `POST /api/redundancy` — 请求体 `{"text": "...", "line": 3}`（`line` 为原始行号），返回：
  - `status: "ok"`：`redundancy`（所选行区间、`derived_low`/`derived_high` 推导端点（`null` 表示无界）、`verdict`（`removable`/`necessary`）、`upper_path`/`lower_path` 推导路径含行号与界值）；
  - 输入无效或原约束冲突时，返回与 `/api/solve` 相同的 `error` / `conflict` 结果。
